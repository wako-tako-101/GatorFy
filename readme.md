Gatorfy 
Gatorfy is a C++ music recommendation program that identifies songs similar to a user-selected track using acoustic characteristics and metadata. It also compares two data structures—a Max Heap and a Red-Black Tree—for ranking and retrieving recommendations efficiently.
Features
- Search for a song by title in a large music dataset.
- Compare a selected song against other tracks using artist and acoustic metadata.
- Assign each candidate a similarity score out of 100.
- Display the highest-scoring recommendations.
- Compare Max Heap and Red-Black Tree insertion and top-recommendation retrieval performance.
- Load and filter a large CSV dataset, skipping records with missing or unusable values.
Technologies
- Language: C++
- Build/development: CMake, CLion
- Libraries: C++ Standard Library (vector, unordered_map, fstream, sstream, algorithm, cmath, chrono)
- Version control: Git and GitHub
Dataset
Gatorfy uses the public Spotify 1.2M+ Songs dataset on Kaggle. The project report describes processing over 1.2 million songs.

The program uses song information including title, artist, album, tempo, loudness, musical key, scale mode, explicit-content status, time signature, and release year.

Dataset setup: Download the dataset from Kaggle and configure the CSV file path according to the project's source code. The exact filename and path depend on the repository configuration.
How Recommendations Work
1. The user searches for and selects a seed song.
2. The program compares that song with other valid songs in the dataset.
3. Each candidate receives a weighted similarity score (maximum 100 points).
4. Candidates are inserted into a Max Heap or Red-Black Tree according to their scores.
5. The program retrieves and displays the top-ranked recommendations.
   
Similarity Scoring
Attribute	Maximum points	Scoring criteria
Artist match	20	Same primary artist: 20; matching featured artist: 10
Tempo	15	Within 5 BPM: 15; 12 BPM: 10; 25 BPM: 5
Loudness	15	Within 1.5 dB: 15; 3.5 dB: 10; 6 dB: 5
Musical key	15	Exact key: 15; compatible key on circle of fifths: 8
Scale mode	10	Both major or both minor: 10
Explicit status	10	Both explicit or both clean: 10
Time signature	10	Matching beats per measure: 10
Release year	5	Within 3 years: 5; within 7 years: 3
Total	100	


Higher scores indicate greater similarity according to these selected characteristics; the score is not a machine-learned prediction of personal taste.
Data Structures
Max Heap
The Max Heap stores scored songs in a vector, keeping the highest-scoring song at the root. It uses heapify-up after insertion and heapify-down after extraction.
- Insertion: O(log n) per song
- Building via individual insertions: O(n log n)
- Retrieving top k from a copied heap: O(n + k log n), including the copy
  
Red-Black Tree
The Red-Black Tree is a self-balancing binary search tree ordered by recommendation score. Rotations and recoloring maintain balanced height during insertion. An ordered traversal retrieves the highest-scoring songs.
- Insertion: O(log n) per song
- Building via individual insertions: O(n log n)
- Retrieving top k: O(log n + k) in a balanced tree, when traversal stops after k results
Both structures support efficient ranking, but their storage layouts and top-k retrieval strategies differ.

Performance Comparison
The project uses C++'s chrono library to benchmark insertion and recommendation retrieval times. The comparison focuses on the cost of loading scored songs into each structure and retrieving the highest-ranked results.


Building and Running
The project was developed using CLion and CMake. With a C++ compiler and CMake installed, the typical workflow is:
git clone https://github.com/wako-tako-101/GatorFy.git
cd GatorFy
cmake -S . -B build
cmake --build build
Next, configure the dataset CSV path expected by the program and run the executable generated by CMake (its name and location depend on the project's CMakeLists.txt and build environment).
